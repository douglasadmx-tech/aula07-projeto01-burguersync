Visão Geral e Objetivo PrincipalO BurguerSync é uma plataforma web full-stack em tempo real orientada a delivery de alimentação no estilo iFood, desenvolvida para o mercado de Ourinhos/SP. O sistema resolve o gap operacional entre o autoatendimento do cliente (carrinho, customização de lanche, endereço e seleção de pagamento) e a linha de produção da cozinha (KDS - Kitchen Display System), eliminando ruídos de comunicação, retrabalho em comandas manuais e lentidão no despacho.O valor final reside em uma interface de alta conversão para o cliente final associada a um painel reativo e síncrono para a equipe operacional da cozinha via Google Firebase Cloud Firestore, com deploy estático resiliente no GitHub Pages.2. Monitora a integridade de payloads, faz sanitização e direciona arquivos transitórios de build para a pasta .tmp/.Layer 3 (Execução & Determinismo): Códigos clientes determinísticos (app.js, firebase-config.js), suíte de validação de schemas, listeners realtime (onSnapshot), mutations (addDoc, updateDoc) e automação CLI (executar.bat, GitHub Actions).3. Tratamento de Erros, Resiliência e Self-Annealing (Auto-Recuperação)Para garantir operação ininterrupta e tolerância a falhas na cozinha e no checkout, o sistema adota o protocolo de Self-Annealing estruturado em três níveis:[Falha Detectada (SDK/DOM/Rede)]
       │
       ▼
[Diagnóstico Automatizado (Layer 2 / Runtime Hook)]
       │
       ├─► Erro de Rede Firestore ──► Chaveia p/ Fallback Offline (IndexedDB / LocalStorage)
       ├─► Payload Inválido ──────► Validação em .tmp/validador.log & Rejeição com Feedback
       └─► Falha de Renderização ──► Fallback Component + Re-render Silencioso
7.1 Protocolos de Resiliência em Runtime:Queda de Conexão Firestore (Offline Persistence):Habilitar o cache offline do Firestore (enableIndexedDbPersistence). Caso a conexão em Ourinhos oscile, os pedidos ficam em buffer local e são descarregados na nuvem no restabelecimento da rede.Reconexão Silenciosa do Listener (Dead-Man Switch):O listener onSnapshot da cozinha possui um heartbeat a cada 30 segundos. Se o canal não responder, o sistema encerra a conexão anterior e remonta a subscrição sem intervenção humana.Validação Estrita de Payload Pré-Envio:Se o cliente tentar submeter um pedido corrompido, a Layer 3 intercepta, armazena o dump do erro em .tmp/erros_transacao.log e exibe mensagem contextual corrigindo o input do usuário sem resetar o carrinho.Ciclo de Correção Contínua (Self-Correction Loop na IA):Caso um teste automatizado ou script de lint falhe durante o build, a orquestração (Layer 2) isola o stacktrace na pasta .tmp/trace.log, executa a correção cirúrgica no arquivo do módulo correspondente e reexecuta os testes antes de liberar o commit para a nuvem.
